## Cost by channel (main run)

Main run: Qwen3-8B on RTX 3090s, 34,864-token KV cache, k = 3 questions per task, 300 tasks (HotpotQA and 2Wiki pooled; `t07_main`). Each cell is a mean per task; file operations count `list_files`, `read_file`, and `write_file` calls.

| Channel | Tokens sent (k) | Prefill computed (k) | Model calls | File operations | Accuracy (%) |
| --- | --- | --- | --- | --- | --- |
| A1 broadcast | 13.3 | 12.4 | 3.0 | 0 | 72.3 |
| A1-zc zero-copy | 13.6 | 4.8 | 3.0 | 0 | 71.6 |
| A2 pipe | 5.6 | 4.7 | 3.0 | 0 | 62.1 |
| B shared files | 38.2 | 9.8 | 17.0 | 14.3 | 62.8 |
| C files + index | 37.4 | 9.8 | 15.9 | 13.2 | 66.3 |
| D handoffs&dagger; | 17.5 | 7.2 | 7.8 | 5.7 | 65.1 |

B and C send 2.9× and 2.8× broadcast's tokens (17.0 and 15.9 model calls per task against 3.0) but compute less prefill (0.79× each), because the prefix cache absorbs the resent conversation; zero-copy sends about as many tokens as broadcast and computes 61% less prefill.

&dagger; D is excluded from the main comparison: agents pass a message of at most 120 words plus file paths.

&Dagger; Qwen3-32B B, C, and D: the size run's own values. Table 10 gives no prefill ratio for the path rerun (whose accuracy the accuracy table shows).

## Run time relative to broadcast

Timing runs, separate from the main and size runs: each channel served alone on one RTX PRO 6000 (Qwen3-8B, 100k-token KV cache, 100 tasks at k = 3), three runs per channel with 6 tasks at a time and two runs of A1, A1-zc, and B with 32 at a time. Each cell is relative to A1 broadcast: the run's wall time (mean over runs), the median task's wall time (per run, then averaged), and vLLM's summed prefill and decode time.

Zero-copy cuts prefill time to 0.49× but its runs take 1.09× broadcast's: decoding is 96% of broadcast's prefill-plus-decode time, and zero-copy generates 1.2× the output tokens. With 32 tasks at a time its median task takes 0.82× but the run 1.00×.
